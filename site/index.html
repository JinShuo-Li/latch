01 / GET STARTED

Your terminal.
Ready for work.

Download a precompiled binary. No Rust toolchain needed. The installer checks SHA256 before installing.

Linux

x86_64 · glibc 2.35+

BASH

curl -fsSL https://jinshuo-li.github.io/latch/install.sh | bash

Installs to ~/.local/bin. Runtime requires Bubblewrap, ripgrep, and Git.

Debian / Ubuntu prerequisites
sudo apt update && sudo apt install bubblewrap ripgrep git

Windows

x86_64 · native MSVC build

POWERSHELL

irm https://jinshuo-li.github.io/latch/install.ps1 | iex

Installs to %LOCALAPPDATA%\Programs\Latch\bin. Requires Git, ripgrep, and a user-owned NTFS workspace.

Native sandbox included. No WSL or compiler needed.

NEXT /

Run latch, use /setup to choose a provider and model, then run latch doctor to check your configuration.

02 / WHY LATCH

Trust the record.
Inspect the work.

Long-running coding work needs more than a chat transcript. Latch makes state, execution, and evidence explicit.

01 / MEMORY

Durable state

An append-only event log preserves task state, tool results, and evidence. Resume a session without losing the record of how you got there.

02 / EXECUTION

Mandatory sandbox

Every command runs inside the platform sandbox. Inspection commands have read-only filesystem access. If the boundary is unavailable, execution stops.

03 / CORRECTNESS

Evidence-bound validation

A pass certifies the workspace state it checked. Later writes make that evidence stale. Completion is grounded in recorded validation.

04 / CONTROL

Terminal-native control

Inspect tool activity, steer a running turn, and choose Ask, Plan, or Work. Use the TUI interactively or the machine CLI in scripts.
